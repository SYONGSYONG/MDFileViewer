# 01. 제품 명세 — 무엇을 만드는가

## 1. 제품 목표

1. 트리에서 폴더를 펼치면 그 안의 md 파일이 폴더와 함께 바로 보이고, 클릭 한 번으로 읽을 수 있다.
2. 기본은 읽기 전용 뷰어라서 실수로 문서를 바꾸지 않고, 필요할 때만 편집 모드로 들어간다.
3. Windows 탐색기에서 우클릭으로 "지금 보고 있는 그 위치"를 바로 연다.
4. 긴 문서도 편하게 읽을 수 있게 밝은/어두운 테마와 줌을 제공한다.
5. Markdown 문법을 모르는 사용자도 도움말을 보며 작성할 수 있다.

## 2. 사용자

- **주 사용자:** 로컬 폴더의 md 문서(README, 설계 문서, 메모 등)를 자주 읽고 가끔 고치는 Windows 사용자.
- **사용 맥락:** 탐색기에서 폴더를 둘러보다가 우클릭으로 열고, 트리를 훑으며 여러 문서를 연달아 읽는다.
  가끔 오타나 내용을 고치고 저장한다.

## 3. 범위

우선순위 표기: **P0** = 사용자가 요청한 핵심 기능, **P1** = MVP에 함께 넣는 보조 기능, **P2** = 후속 후보(§8).

## 5. 기능 명세

### F-01. 시작과 명령줄 인수 (P0)

| 실행 형태 | 동작 |
|-----------|------|
| `MDFileViewer.exe` (인수 없음) | 마지막으로 선택했던 폴더를 펼쳐 선택한 상태로 시작한다. 기록이 없거나 폴더가 사라졌으면 "내 PC"만 펼친 상태로 시작한다. 지난번 닫을 때 열려 있던 문서 탭을 되살린다(F-17). |
| `MDFileViewer.exe "<폴더 경로>"` | 트리를 그 폴더까지 펼쳐 선택하고, 그 폴더도 펼쳐 안의 하위 폴더와 md 파일을 보여 준다. 뷰어는 "왼쪽 트리에서 md 파일을 선택하세요" 안내를 보여 준다. |
| `MDFileViewer.exe "<md 파일 경로>"` | 트리를 파일이 있는 폴더까지 펼치고, 트리에서 그 파일을 선택한 뒤 뷰어에 표시한다. |
| `MDFileViewer.exe "<md가 아닌 파일 경로>"` | 그 파일이 있는 폴더를 연다(폴더 경로를 준 것과 같다). 탐색기 메뉴는 md 파일에만 붙으므로 직접 입력한 경우뿐이다. |
| `MDFileViewer.exe --register` / `--unregister` | 창을 띄우지 않고 탐색기 메뉴를 등록/해제한 뒤 결과를 알리고 종료한다 (F-13). `--silent`를 함께 주면 결과 창을 띄우지 않는다(설치 파일의 제거 단계용). |

**규칙과 예외**

- 인수로 받은 경로가 없으면 "경로를 찾을 수 없습니다: <경로>"를 알리고 인수 없는 실행과 같이 시작한다.
- 상대 경로는 현재 작업 폴더를 기준으로 절대 경로로 바꾼다.
- 드라이브 루트에서 빈 공간 우클릭으로 실행하면 인수가 `C:"`처럼 깨져 들어오는 경우가 있으므로
  (`"C:\"`의 `\"`가 따옴표 이스케이프로 해석됨) `C:\`로 보정한다.
- 이미 열린 창이 있으면 새 창을 띄우지 않고 그 창에서 연다(F-23, 기본값). 설정에서 끄면 실행할 때마다 새 창을 연다.
  (처음에는 늘 새 창이었다 — 검토 항목 3. 2026-11-22 사용자 선택으로 바꿨다.)

**수용 기준**

- 탐색기에서 폴더 우클릭 → "MDFileViewer로 열기" → 트리에 그 폴더가 선택되어 화면에 보이고(스크롤 포함) 그 폴더의 md 파일이 트리에 보인다.
- md 파일 우클릭으로 실행하면 그 파일이 뷰어에 표시되고 트리에서도 선택되어 있다.

### F-02. 탐색기 트리 (P0)

- **루트:** "내 PC" 노드 하나. 그 아래에 사용할 수 있는(준비된) 드라이브를 `볼륨 이름 (C:)` 형태로 보여 준다.
  네트워크 드라이브도 포함한다.
- **표시 대상:** 폴더와 md 파일(F-03)을 함께 보여 준다. 한 폴더의 자식은 하위 폴더를 먼저, 그다음 md 파일을 둔다.
- **지연 로딩:** 노드를 펼칠 때 하위 폴더와 md 파일을 백그라운드에서 읽는다. 읽는 동안 "불러오는 중…" 자식 노드를 보여 준다.
  하위 폴더도 md 파일도 없는 폴더에는 펼침 화살표를 표시하지 않는다. md 파일이 없는 폴더도 트리에 그대로 보인다.
- **정렬:** 폴더끼리, md 파일끼리 각각 이름 오름차순, 대소문자 무시.
- **숨김:** 숨김·시스템 속성 폴더는 보여 주지 않는다.
- **접근 거부:** 권한이 없는 폴더는 펼쳐도 비어 있고, 툴팁으로 "접근 권한이 없습니다"를 보여 준다. 앱은 멈추지 않는다.
- **선택:** 폴더를 선택하면 주소 표시줄과 제목 표시줄(문서가 없을 때)이 그 폴더로 바뀐다. 뷰어에 열린 문서는 그대로 둔다.
  md 파일을 선택하면 연다(F-03).
- **시작 폴더 자동 펼침:** 경로의 각 단계를 차례로 펼친 뒤 마지막 폴더를 선택하고, 그 폴더도 펼쳐 안의 md 파일을 보여 주며,
  화면에 보이도록 스크롤한다. md 파일을 열며 시작할 때는 그 파일 노드를 선택한다.
- **가로 스크롤:** 사용자가 트리 행을 클릭하거나 키보드로 옮길 때는 가로 스크롤 위치를 바꾸지 않는다 — 필요하면 세로로만 스크롤한다.
  시작 경로·주소 표시줄·링크처럼 앱이 선택을 옮길 때만, 그 행의 왼쪽 끝이 화면 밖이면 가로로도 맞춘다.
- **새로고침(`F5`):** 선택한 폴더(md 파일을 선택했으면 그 파일이 있는 폴더)의 하위 폴더·md 파일과 열린 문서를 다시 읽는다.
  선택한 md 파일은 계속 선택되어 있고, 그 파일이 없어졌으면 그 파일이 있던 폴더를 선택한다.
  펼쳐 둔 폴더는 F-18이 자동으로 다시 읽으므로, `F5`는 감시가 안 되는 위치(일부 네트워크 공유)나 드라이브 목록을 다시 읽을 때 쓴다.
- **폴더 열기(`Ctrl+O`, P1):** 폴더 선택 대화상자로 고른 폴더로 이동한다.
- **주소 표시줄(P1):** 툴바에 현재 폴더 경로(md 파일을 선택했으면 그 파일이 있는 폴더)를 보여 준다. 폴더나 md 파일 경로를 입력하고
  `Enter`를 누르면 그 폴더로 이동하거나 그 파일을 연다.
- **노드 우클릭 메뉴(P1):** 폴더는 "탐색기에서 열기", "경로 복사", "즐겨찾기에 추가"(F-16, 이미 있으면 "즐겨찾기에서 제거").
  md 파일은 "새 탭으로 열기", "편집 모드로 열기", "탐색기에서 위치 열기", "경로 복사". 드라이브도 폴더와 같다.

**수용 기준**

- `C:\Windows\System32`처럼 하위 폴더가 많은 노드를 펼쳐도 UI가 멈추지 않는다.
- 접근 거부 폴더를 펼쳐도 오류 대화상자 없이 계속 쓸 수 있다.
- 가로 스크롤이 생길 만큼 깊은 폴더에서 트리 행을 클릭해도 가로 스크롤 위치가 바뀌지 않는다.

### F-03. 트리의 md 파일 (P0)

2026-11-17 사용자 결정으로 별도의 md 파일 목록 창(직속/하위 폴더 포함 토글, 이름·수정한 날짜·크기 열과 정렬, 목록 개수)을 없애고
md 파일을 트리(F-02)에 합쳤다. 크기·수정 시각은 상태 표시줄(F-15)에서 본다.

- **대상:** `.md`, `.markdown` 파일(대소문자 무시). (검토 항목 5) 숨김·시스템 속성 파일은 보여 주지 않는다.
- **위치:** 각 폴더 노드의 자식으로, 하위 폴더 다음에 이름 오름차순(대소문자 무시)으로 보여 준다. md 파일 노드에는 펼침 화살표가 없다.
- **열기:** md 파일 노드를 클릭하면(선택이 바뀌면) 미리보기 탭(F-17)으로 연다. 키보드 `↑`/`↓`로 옮겨도 선택한 파일이 열린다.
  더블클릭하면 고정 탭으로 연다.
- **우클릭 메뉴(P1):** F-02의 노드 우클릭 메뉴.
- 편집 중인 문서에 저장하지 않은 변경이 있어도 다른 md 파일을 고르면 확인 없이 연다 — 그 변경은 원래 탭에 남는다(F-17).
- 하위 폴더까지 한꺼번에 md 파일을 찾는 기능은 후속 후보(§8 전체 검색)다.

**수용 기준**

- 폴더를 펼치면 하위 폴더 다음에 md 파일이 보이고, md 파일을 누르면 뷰어에 열린다.
- md 파일 1,000개가 있는 폴더를 펼쳐 0.5초 안에 트리에 표시한다 (§7 성능 목표).

### F-04. 뷰어 — Markdown 렌더링 (P0)

- **렌더링:** Markdig로 HTML을 만들어 WebView2에 표시한다.
- **지원 문법:** CommonMark, GFM 표, 작업 목록, 취소선, 자동 링크, 각주, 제목 앵커(제목마다 id 생성).
- **YAML front matter:** 문서 맨 앞 `---`로 둘러싼 메타데이터는 표시하지 않는다.
- **코드 블록:** 고정폭 글꼴, 구분되는 배경, 긴 줄은 가로 스크롤. 구문 색상은 F-22, ```` ```mermaid ```` 블록의 그림은 F-25.
- **원시 HTML:** 문서 안의 HTML(`<br>`, `<details>`, `<img>` 등)은 표시한다. 단, 문서 안의 스크립트는 실행하지 않고
  `iframe`·`object`·`form`은 막는다 (02 §6 보안). `<meta>` 태그는 글자 그대로 보여 준다 — 문서를 열기만 해도 다른 주소로
  이동시키는 `<meta http-equiv="refresh">`를 막기 위해서다 (02 §6.4).
- **텍스트 선택·복사:** 마우스로 선택해 `Ctrl+C`로 복사할 수 있다. 문서 영역 우클릭 메뉴에는 글자를 선택했을 때 "복사"만 나온다.
- **빈 상태:** 파일을 고르지 않았으면 "왼쪽 트리에서 md 파일을 선택하세요"를 보여 준다.
- **큰 파일:** 5MB를 넘으면 "파일이 큽니다(○○MB). 열까요?"를 확인한 뒤 연다. 새 탭에서 취소하면 그 탭에는 "큰 파일이라 열지 않았습니다"를
  보여 주고(이전 문서를 남기지 않는다 — 이전 문서를 이 파일로 편집·저장하게 되므로), 탭을 다시 누르면 다시 묻는다(2026-11-18).
- **인코딩:** UTF-8(BOM 유무 모두), UTF-16(BOM 있음)을 읽는다. BOM 없는 파일이 UTF-8로 해석되지 않으면
  CP949로 연다. 판별한 인코딩은 상태 표시줄에 보여 준다. (CP949는 추가 패키지 없이 동작함을 PoC-4로 확인)
  UTF-32는 지원하지 않는다.
- **손상된 파일:** 판별한 인코딩으로 풀 수 없는 바이트가 있으면(예: BOM은 UTF-8인데 본문에 CP949 바이트가 섞임) 그 자리를
  `�`(U+FFFD)로 바꿔 보여 주고, 상태 표시줄에 "일부 글자를 읽을 수 없습니다 — 저장할 수 없습니다"를 보여 준다.
  이 파일은 저장할 수 없다(F-07·F-10). 그대로 저장하면 원래 바이트를 잃기 때문이다.
- **읽기 실패:** 파일이 사라졌거나 잠겨 있으면 뷰어에 오류 안내를 보여 주고, 사라진 파일은 새로고침 때 트리에서 빠진다.

**수용 기준**

- 표, 작업 목록, 각주, 코드 블록, 인용, 중첩 목록이 들어간 샘플 문서가 밝게/어둡게 테마 모두에서 깨지지 않고 보인다.
- `<script>alert(1)</script>`가 들어간 문서를 열어도 스크립트가 실행되지 않는다.

### F-05. 링크·이미지 처리 (P1)

뷰어와 미리보기에서 링크를 클릭하면 링크 종류에 따라 다음과 같이 처리한다.

| 링크 종류 | 예 | 동작 |
|-----------|----|------|
| 웹·메일 | `https://…`, `http://…`, `mailto:…` | 기본 브라우저·메일 앱으로 연다 |
| 문서 내 앵커 | `#설치-방법` | 같은 문서 안의 해당 제목으로 스크롤한다 |
| 다른 md 파일 | `./guide.md`, `../docs/a.md#섹션` | 앱 안에서 그 파일을 열고, 트리 선택도 그 파일로 옮긴다. 앵커가 있으면 그 위치로 스크롤한다 |
| 그 밖의 로컬 파일 | `./setup.exe`, `./spec.pdf` | **실행하지 않는다.** 탐색기를 열어 해당 파일을 선택해 보여 준다 |
| 없는 로컬 파일 | — | 상태 표시줄에 "파일을 찾을 수 없습니다"를 보여 준다 |
| 그 밖의 스킴 | `javascript:`, `file:`, `data:` 등 | 무시한다 |

- **이미지:** 상대 경로 이미지는 문서가 있는 폴더를 기준으로 표시한다(`../images/a.png` 포함).
  원격 이미지(README 배지 등)도 표시한다. 없는 이미지는 깨진 이미지로 보일 뿐 오류를 띄우지 않는다.
  원격 이미지는 열자마자 그 서버에 요청이 가므로, 남이 만든 문서를 열면 그 서버가 열람 시각·IP를 알 수 있다(추적 픽셀). 보안 리뷰(2026-11-18)
  뒤 사용자 결정으로 허용을 유지하고 사용법 매뉴얼에 알린다. 차단 옵션은 후속 후보(§8).
- 다른 md 파일 링크는 미리보기 탭으로 연다(F-17). 편집 중인 변경은 원래 탭에 남는다.
- 위 동작은 **사용자가 링크를 눌렀을 때만** 한다. 문서가 스스로 일으키는 이동(`<meta http-equiv="refresh">` 등)은 무시한다 —
  문서를 여는 것만으로 브라우저나 탐색기가 열리면 안 된다. meta refresh는 F-04대로 글자로 바꿔 이동 자체가 일어나지 않게 한다.
- 문서 루트 밖을 가리키게 만든 링크(인코딩된 경로 구분자 등)는 "그 밖의 스킴"처럼 무시한다.

**수용 기준**

- 위 표의 링크 종류마다 샘플을 넣은 문서에서 각 링크가 표대로 동작한다.

### F-06. 줌 (P0)

- **툴바:** `[−] [100%] [+]`. 가운데에 현재 배율을 정수 %로 보여 준다.
- **시작 배율:** 100%. (검토 항목 4)
- **단계:** 50 · 67 · 75 · 80 · 90 · **100** · 110 · 125 · 150 · 175 · 200 · 250 · 300 (%).
  `+`는 현재보다 큰 가장 가까운 단계로, `−`는 현재보다 작은 가장 가까운 단계로 간다.
- **범위:** 50%~300%. 끝 단계에서는 해당 버튼을 비활성화한다.
- **리셋:** 가운데 배율 표시를 클릭하면 100%로 돌아간다.
- **단축키:** `Ctrl+=`·`Ctrl++`(숫자 패드 포함) 확대, `Ctrl+-` 축소, `Ctrl+0` 100%, `Ctrl+마우스 휠` 확대·축소.
- `Ctrl+휠`은 문서 영역(WebView2)이 자체 단계로 처리한다. 단계 사이 배율이 되면 실제 배율을 보여 주고, 다음 `+`/`−`는
  가장 가까운 다음 단계로 간다. `Ctrl+휠`로 50%~300% 범위를 벗어나면 가까운 끝 값으로 되돌린다.
- `Ctrl+=`·`Ctrl+-`·`Ctrl+0`은 앱이 처리하므로 위 단계를 그대로 따른다 (PoC-3).
- **적용 대상:** 문서 표시 영역(보기 모드의 뷰어, 편집 모드의 미리보기). 앱 UI 크기와 편집기 글꼴은 바뀌지 않는다.
- 실행 중에는 다른 파일을 열어도 배율을 유지한다.

**수용 기준**

- 100%에서 `+`를 두 번 누르면 125%, `−`를 세 번 더 누르면 90%가 된다. `100%` 표시를 누르면 100%로 돌아간다.
- 300%에서는 `+`가, 50%에서는 `−`가 비활성화된다.

### F-07. 모드 전환 — 보기 ↔ 편집 (P0)

- **전환:** 툴바의 **편집** 토글 버튼 또는 `Ctrl+E`. 편집 모드에서는 버튼이 **보기**로 바뀐다.
- 파일이 열려 있을 때만 전환할 수 있다.
- **보기 → 편집:**
  - 문서 영역이 **편집기(왼쪽) | 미리보기(오른쪽)** 2분할이 된다.
  - 탐색 패널(트리)을 자동으로 접는다. 접힌 패널은 왼쪽 가장자리 버튼이나 `Ctrl+B`로 다시 펼친다. (검토 항목 1)
    툴바 맨 왼쪽의 패널 버튼으로도 어느 모드에서든 접고 편다(2026-11-18 사용자 요청).
  - 편집 모드임을 알 수 있도록 툴바 아래에 편집 모드 색 막대와 "편집 중" 표시를 보여 준다 (03).
- **편집 → 보기:** 저장하지 않은 변경이 있으면 F-10 확인을 거친다. 보기 모드로 돌아오면 탐색 패널을 원래 상태로 되돌린다.
- **분할 비율:** 기본 50:50, 가운데 구분선을 끌어 바꾼다. 비율은 설정에 저장한다.
- **읽기 전용 파일:** 편집 모드에 들어갈 수는 있지만 상단에 "읽기 전용 파일이라 저장할 수 없습니다"를 보여 주고 저장을 비활성화한다.
- **손상된 파일(F-04):** 읽기 전용 파일과 같이 편집 모드에 들어갈 수는 있지만 "읽을 수 없는 글자가 있어 저장할 수 없습니다"를 보여 주고 저장을 비활성화한다.

**수용 기준**

- `Ctrl+E`를 누르면 편집기와 미리보기가 나란히 나오고, 다시 누르면 뷰어로 돌아온다.

### F-08. 편집기 (P0)

- **컴포넌트:** AvalonEdit.
- **구문 강조:** 제목, 굵게·기울임, 인라인 코드·코드 블록, 링크, 인용, 목록 기호. 테마별 색을 따로 둔다 (03).
- **기본 편집:** 실행 취소/다시 실행(`Ctrl+Z`/`Ctrl+Y`), 잘라내기·복사·붙여넣기, 전체 선택.
- **보기 옵션(P1):** 줄 번호 표시(기본 켬), 자동 줄 바꿈(기본 켬). 둘 다 설정에 저장한다.
- **찾기(P1):** `Ctrl+F` — AvalonEdit 검색 패널. 바꾸기는 P2.
- **탭 키:** 공백 4칸을 넣는다.
- **글꼴:** 고정폭 글꼴(03 타이포그래피).

### F-09. 미리보기 (P0)

- 입력이 멈추고 **300ms** 뒤에 미리보기를 다시 그린다 (디바운스).
- 다시 그려도 미리보기의 스크롤 위치를 유지한다.
- **스크롤 동기화(P1):** 편집기를 스크롤하면 미리보기도 같은 비율 위치로 스크롤한다. 줄 단위 정밀 동기화는 P2.
- 미리보기에도 줌(F-06), 테마(F-11), 링크 처리(F-05)가 똑같이 적용된다.

**수용 기준**

- 편집기에 `# 제목`을 입력하면 1초 안에 미리보기에 제목이 나타난다.

### F-10. 저장과 미저장 변경 보호 (P0)

- **저장:** `Ctrl+S` 또는 툴바 저장 버튼(편집 모드에서만 보임). 저장하면 상태 표시줄에 "저장됨"을 잠시 보여 준다.
- **변경 표시:** 저장하지 않은 변경이 있으면 제목 표시줄을 `*README.md - MDFileViewer`처럼 표시하고 저장 버튼을 강조한다.
- **형식 보존:** 원래 인코딩, BOM 유무, 줄 끝 방식(CRLF/LF)을 유지해 저장한다. 줄 끝이 섞여 있으면 더 많이 쓰인 방식으로 맞춘다.
- **안전한 저장:** 같은 폴더의 임시 파일에 먼저 쓰고 원본과 교체한다. 저장 도중 실패해도 원본이 깨지지 않는다.
- **저장 실패:** 권한·잠금 등으로 실패하면 원인을 대화상자로 알리고, 편집 내용은 그대로 둔다.
- **원래 인코딩으로 나타낼 수 없는 문자:** CP949 파일에 이모지처럼 CP949에 없는 문자를 넣고 저장하면, 문자를 `?`로 바꾸지 않고
  "CP949로 나타낼 수 없는 글자가 있습니다. UTF-8로 바꿔 저장할까요?"를 묻는다(2026-11-18 결정). `[UTF-8로 저장]`을 누르면 UTF-8(BOM 없음)로
  저장하고 상태 표시줄 인코딩도 바꾼다. `[취소]`면 저장하지 않고 파일·편집 내용을 그대로 둔다.
- **손상된 파일:** F-04의 손상된 파일은 저장 버튼과 `Ctrl+S`를 비활성화한다. 탭을 닫다가 확인 대화상자에서 `[저장]`을 눌렀는데 저장할 수 없는
  파일(읽기 전용·손상)이면 이유를 대화상자로 알린다(2026-11-18).
- **바깥에서 바뀐 파일 덮어쓰기(2026-11-18 사용자 결정):** 마지막으로 읽거나 저장한 뒤 다른 프로그램이 파일을 바꿨으면, 저장 전에
  "○○을(를) 다른 프로그램이 바꿨습니다. 덮어쓰면 그 변경이 사라집니다. 덮어쓸까요?"를 묻는다 — `[덮어쓰기]` `[취소]`.
- **저장 중 입력:** 저장하는 동안 친 글자는 파일에 없으므로 변경 있음 표시(`*`·●)를 그대로 둔다(2026-11-18).
- **확인 시점:** 저장하지 않은 변경이 있을 때 아래 동작을 하면 확인 대화상자를 먼저 띄운다.
  - 그 탭 닫기(F-17)
  - 보기 모드로 전환
  - 새로고침(`F5`)으로 파일 다시 읽기
  - 창 닫기 — 저장하지 않은 탭마다 차례로 묻는다
- 다른 md 파일 열기(트리 선택, 미리보기 링크)·다른 탭으로 옮기기는 묻지 않는다. 변경은 그 탭에 그대로 남는다(F-17, 2026-11-18 결정).
- **확인 대화상자:** "README.md의 변경 내용을 저장할까요?" — `[저장]` `[저장 안 함]` `[취소]`.
  `[취소]`를 누르면 하려던 동작을 하지 않는다. `[저장]`이 실패하면 하려던 동작도 하지 않는다.
- 자동 저장은 하지 않는다. (검토 항목 2)

**수용 기준**

- UTF-8(BOM 없음)+LF 파일을 고쳐 저장한 뒤 바이트를 비교하면 BOM이 생기지 않고 줄 끝이 LF로 유지된다.
- 미저장 상태로 창을 닫으려 할 때 `[취소]`를 누르면 창이 닫히지 않고 편집 내용이 남아 있다.

### F-11. 테마 — 시스템 / 밝게 / 어둡게 (P0)

- **선택지:** 시스템 설정 따르기(기본), 밝게, 어둡게. 툴바 테마 버튼을 누르면 세 가지를 고르는 메뉴가 열린다.
- **적용 범위:** 앱 UI(툴바, 트리, 상태 표시줄, 대화상자), Windows 11 제목 표시줄, 뷰어·미리보기 문서 스타일,
  편집기 구문 강조 색, 도움말 창.
- **시스템 설정 따르기:** Windows의 앱 모드(밝게/어둡게)를 따르고, 실행 중에 Windows 설정을 바꿔도 바로 반영한다.
- 테마를 바꿔도 열린 문서와 스크롤 위치는 그대로다.
- 선택한 테마는 설정에 저장한다.

**수용 기준**

- 어둡게 테마에서 트리, 문서, 편집기, 도움말 창 어디에도 밝은 배경이 남지 않는다.
- 시스템 설정 따르기 상태에서 Windows 앱 모드를 바꾸면 재시작 없이 테마가 바뀐다.

### F-12. 도움말 — Markdown 문법 (P0)

- **열기:** 툴바 `?` 버튼 또는 `F1`.
- **창:** 메인 창과 따로 움직이는 모달리스 창이다. 편집하면서 옆에 띄워 둘 수 있다. 이미 열려 있으면 앞으로 가져온다.
- **구성:** 문법마다 **작성 예시(원문)**와 **결과(렌더링)**를 함께 보여 준다. 왼쪽에 문법 목차가 있다.
- **다루는 문법:**
  1. 제목 (`#` ~ `######`)
  2. 문단과 줄 바꿈 (빈 줄, 줄 끝 공백 두 칸, `<br>`)
  3. 강조 — 굵게, 기울임, 굵은 기울임, 취소선
  4. 목록 — 순서 없는 목록, 순서 있는 목록, 중첩 목록
  5. 작업 목록 (`- [ ]`, `- [x]`)
  6. 링크 — 인라인, 참조형, 자동 링크, 문서 안 앵커, 다른 md 파일
  7. 이미지 — 상대 경로, 대체 텍스트
  8. 인용 (중첩 포함)
  9. 코드 — 인라인 코드, 코드 블록, 언어 지정
  10. 표 — 열 정렬(`:---`, `:---:`, `---:`)
  11. 수평선
  12. 각주
  13. 이스케이프 (`\*` 등)
  14. HTML 사용과 이 앱의 제한(스크립트 미실행)
  15. YAML front matter
- **단축키 표:** §6 단축키를 도움말 끝에 함께 싣는다.
- **앱 정보:** 도움말 아래쪽에 앱 버전을 보여 준다.
- 도움말 내용은 앱에 내장한 md 문서이고 뷰어와 같은 렌더러로 보여 주므로 테마·줌이 같게 적용된다.

### F-13. 탐색기 우클릭 메뉴 — 셸 통합 (P0)

- **메뉴 이름:** "MDFileViewer로 열기" (앱 아이콘 표시).
- **대상과 동작:**

| 우클릭 위치 | 시작 동작 |
|-------------|-----------|
| 폴더 아이콘 | 그 폴더를 선택해 시작 |
| 폴더 안 빈 공간(배경) | 지금 보고 있는 폴더를 선택해 시작 |
| `.md`·`.markdown` 파일 | 파일이 있는 폴더를 선택하고 그 파일을 열어 시작 |

- **등록·해제:** 앱 메뉴 `⋯ → 탐색기 메뉴 등록` / `탐색기 메뉴 해제`, 또는 `MDFileViewer.exe --register` / `--unregister`.
- **범위:** 현재 사용자에게만 등록한다. 관리자 권한이 필요 없다.
- **여러 개 선택:** 항목을 하나만 선택했을 때만 메뉴를 보여 준다.
- **exe 위치 변경(P1):** 등록된 실행 경로가 지금 실행 중인 exe와 다르면 시작할 때 "탐색기 메뉴를 현재 위치로 다시 등록할까요?"를 알린다.
  `[나중에]`를 누르면 그 exe 위치에서는 다시 묻지 않는다(설정에 기억, 2026-11-18 사용자 결정 — `⋯` 메뉴로는 언제든 등록할 수 있다).
  이 exe로 등록했는데 네 곳 중 일부 키만 없으면 묻지 않고 다시 채운다. 등록이 중간에 실패하면 쓴 키를 지워 일부만 등록된 채 남기지 않는다.
- **해제:** 앱이 만든 레지스트리 키만 지운다.
- **제약 — Windows 11:** 이 방식으로 등록한 메뉴는 Windows 11 새 우클릭 메뉴의 최상단에는 나오지 않고,
  **"더 많은 옵션 표시"**(또는 `Shift+F10`) 안에 나온다. 최상단 노출은 P2다. (검토 항목 10, 02 §8)
- 드라이브 아이콘(예: "내 PC"의 C: 드라이브) 우클릭은 대상이 아니다(P2). 드라이브 루트 안 빈 공간 우클릭은 대상이다.

**수용 기준**

- 등록 후 세 위치에서 메뉴가 보이고 표의 동작대로 시작한다. 해제 후에는 세 위치 모두에서 메뉴가 사라진다.

### F-14. 설정 저장·복원 (P1)

- **저장 위치:** `%APPDATA%\MDFileViewer\settings.json`.
- **저장 항목:** 창 위치·크기·최대화 여부, 트리 패널 너비, 편집 분할 비율, 테마,
  마지막 폴더, 편집기 줄 번호·자동 줄 바꿈, 즐겨찾기(F-16), 열린 탭과 활성 탭(F-17), 목차 패널 여닫기(F-21), 창 하나로 열기(F-23).
  줌 배율은 저장하지 않는다(F-06).
- **저장 시점:** 창을 닫을 때. 즐겨찾기는 바꿀 때마다 바로 저장한다(창을 닫지 못하고 끝나도 남게). 창 하나로 열기도 바꿀 때 바로 저장한다
  (다음 실행이 읽어야 하므로).
- **여러 창:** 창마다 따로 쓰므로 마지막에 닫은 창의 값이 남는다. 즐겨찾기는 저장할 때 파일의 목록을 다시 읽어 합치지 않는다 — 한 창에서 바꾼
  즐겨찾기는 다른 창을 닫을 때 그 창이 가진 목록으로 덮일 수 있다("여러 창으로 열기"로 쓸 때 생기는 제약). 창 하나로 열기 값은 닫을 때
  파일의 값을 따르므로 덮이지 않는다.
- **복원 예외:** 저장된 창 위치가 지금 연결된 모니터 밖이면 기본 위치에 띄운다.
- **손상:** 설정 파일을 읽을 수 없으면 기본값으로 시작하고, 손상된 파일은 `settings.json.bak`으로 남긴다.

### F-15. 상태 표시줄 (P1)

- 열린 파일의 전체 경로, 인코딩, 줄 끝 방식, 크기, 수정한 시각.
- 편집 모드에서는 커서 위치(줄:열).
- 일시 메시지("저장됨", "파일을 찾을 수 없습니다" 등)를 몇 초 동안 보여 준다.

### F-16. 즐겨찾기 (P0, 2026-11-18 사용자 요청)

- **위치:** 트리 맨 위, "내 PC" 위에 "즐겨찾기" 노드 하나. 처음에는 펼친 상태다. 즐겨찾기가 없으면 펼침 화살표 없이 빈 노드로 보이고,
  툴팁으로 "폴더를 우클릭해 즐겨찾기에 추가하세요"를 보여 준다.
- **항목:** 등록한 폴더(드라이브 포함)를 등록한 순서대로 보여 준다. 이름은 폴더 이름(드라이브는 `C:\`), 툴팁은 전체 경로.
  항목은 일반 폴더처럼 펼쳐 하위 폴더와 md 파일을 보고, md 파일을 고르면 연다.
- **추가:** 트리에서 폴더·드라이브를 우클릭 → "즐겨찾기에 추가". 같은 경로(대소문자 무시)는 한 번만 들어간다.
- **제거:** 즐겨찾기 항목을 우클릭 → "즐겨찾기에서 제거". 같은 폴더를 "내 PC" 쪽에서 우클릭해도 "즐겨찾기에서 제거"가 나온다.
- **순서 바꾸기:** 즐겨찾기 항목 우클릭 → "위로 이동" / "아래로 이동".
- **없어진 폴더:** 지워졌거나 연결이 끊긴 폴더도 목록에 남기고, 펼치면 비어 있다(F-02 실패 표시와 같다). 지우려면 직접 제거한다.
- **선택:** 즐겨찾기 항목을 고르면 주소 표시줄·제목이 그 폴더로 바뀐다(F-02 폴더 선택과 같다). 주소 표시줄·링크·시작 인수로 이동할 때는
  "내 PC" 쪽 노드를 펼쳐 고른다.
- **저장:** 설정 파일(F-14)에 바로 저장한다.

**수용 기준**

- 폴더를 우클릭해 즐겨찾기에 추가하면 "즐겨찾기" 아래에 나타나고, 앱을 다시 시작해도 남아 있다. 제거하면 사라진다.

### F-17. 문서 탭 (P0, 2026-11-18 사용자 요청)

- **위치:** 문서 영역 위(보기 모드의 뷰어, 편집 모드의 편집기|미리보기 위)에 탭 줄 하나. 탭이 없으면 탭 줄을 접는다.
- **탭 표시:** 파일 이름, 저장하지 않은 변경이 있으면 이름 뒤 `●`, 닫기 버튼 `×`. 툴팁은 전체 경로. 활성 탭은 문서 면과 같은 색으로 이어진다.
- **미리보기 탭(VS Code 방식):** 트리 클릭·키보드 이동·링크로 연 파일은 미리보기 탭(이름을 기울임꼴로 표시)에 연다. 미리보기 탭은 하나뿐이고,
  다른 파일을 열면 그 탭의 파일이 바뀐다. 아래 경우 고정 탭(바꾸지 않는 탭)이 된다.
  - 트리에서 md 파일을 더블클릭, 트리 우클릭 "새 탭으로 열기"
  - 탭을 더블클릭
  - 편집 모드로 들어감(저장하지 않은 변경이 생기는 탭은 늘 고정이다)
  시작 인수·주소 표시줄로 연 파일은 고정 탭으로 연다(일부러 고른 파일이므로).
- **이미 열린 파일:** 트리·링크·주소로 이미 탭에 있는 파일을 열면 새 탭을 만들지 않고 그 탭으로 간다(앵커가 있으면 그 위치로).
- **탭 전환:** 탭을 누르거나 `Ctrl+Tab`/`Ctrl+Shift+Tab`. 전환하면 트리 선택도 그 파일로 옮긴다(F-02 앱이 고를 때와 같다).
  탭마다 보기/편집 모드, 저장하지 않은 편집 내용, 실행 취소 기록을 따로 가진다. 줌 배율은 모든 탭이 같다(F-06).
- **탭 닫기:** `×`, 가운데 버튼 클릭, `Ctrl+W`, 탭 우클릭 "닫기". 저장하지 않은 변경이 있으면 F-10 확인을 거친다. 닫은 탭이 활성이었으면
  오른쪽 탭(없으면 왼쪽 탭)으로 간다. 마지막 탭을 닫으면 뷰어는 빈 상태 안내로 돌아간다.
- **탭 우클릭 메뉴:** 닫기, 다른 탭 모두 닫기, 탭 고정(미리보기 탭일 때), 경로 복사, 탐색기에서 위치 열기.
- **바깥에서 사라진 파일:** 탭은 남기고, 그 탭을 열면 F-04 읽기 실패 안내를 보여 준다.
- **복원:** 창을 닫을 때 열린 탭(경로·미리보기 여부)과 활성 탭을 설정에 저장하고, 인수 없이 실행하면 되살린다. 없어진 파일의 탭은 빼고,
  저장하지 않은 편집 내용은 되살리지 않는다(창을 닫을 때 F-10이 이미 물었다). 폴더·파일 인수로 실행하면 지난 탭을 되살리지 않는다.
- 탭이 많아 줄을 넘으면 탭 줄을 가로로 스크롤한다(휠 또는 양 끝 화살표).

**수용 기준**

- 트리에서 파일 A, B를 차례로 클릭하면 미리보기 탭 하나가 A → B로 바뀐다. B를 더블클릭하면 고정되고, 이어서 C를 클릭하면 새 미리보기 탭이 생긴다.
- 탭 A에서 고치고 저장하지 않은 채 탭 B로 갔다가 A로 돌아오면 고친 내용이 그대로 있고, 실행 취소도 된다.
- 탭 3개를 연 채 닫고 인수 없이 다시 실행하면 같은 탭 3개와 활성 탭이 되살아난다.

### F-18. 자동 새로고침 (P1, 2026-11-18 사용자 지적)

검토 항목 8에서 후속(P2)으로 두었던 파일 감시를 사용자 지적("폴더에 새 파일이 추가됐는데 업데이트가 안 된다")으로 범위에 넣었다.

- **트리:** 펼쳐 둔 폴더(하위 폴더 포함 아님 — 그 폴더 바로 안)에 폴더·md 파일이 생기거나, 지워지거나, 이름이 바뀌면 그 폴더의 자식을 자동으로 다시 읽는다.
  `F5`와 같은 방식이라 펼쳐 둔 하위 트리와 선택은 유지된다. 여러 변경이 한꺼번에 오면 마지막 변경 뒤 잠깐(0.5초) 기다렸다가 한 번만 다시 읽는다.
  폴더를 접으면 그 폴더의 감시를 멈춘다.
- **열린 문서:** 탭에 열린 파일이 앱 밖에서 바뀌면, 저장하지 않은 변경이 없는 탭은 자동으로 다시 읽는다(활성 탭은 스크롤을 유지하며 본문만 교체).
  저장하지 않은 변경이 있는 탭은 덮지 않고 상태 표시줄에 "다른 프로그램이 이 파일을 바꿨습니다"를 한 번 보여 준다(같은 변경으로 되풀이하지 않는다).
  앱이 직접 저장한 변경에는 반응하지 않는다. 다시 읽는 동안 입력하면 그 입력을 지키고 충돌로 알린다.
- **다시 읽기 실패:** 다른 프로그램이 쓰는 중이라 잠깐 잠겨 다시 읽지 못하면, 보던 문서와 감시를 그대로 두고 상태 표시줄에
  "바깥에서 바뀐 파일을 다시 읽지 못했습니다 — F5로 다시 읽으세요"를 보여 준다(2026-11-18).
- 상위 폴더를 접으면 그 아래 펼쳐 둔 폴더들의 감시도 멈추고, 다시 펼치면 이어서 감시한다(2026-11-18).
- **감시할 수 없는 위치:** 감시를 시작하지 못하는 위치(일부 네트워크 공유 등)는 로그만 남기고 `F5`로 다시 읽는다.

**수용 기준**

- 펼쳐 둔 폴더에 탐색기로 md 파일을 새로 만들면 몇 초 안에 트리에 나타나고, 지우면 사라진다.
- 다른 편집기에서 열린 문서를 고쳐 저장하면 뷰어 내용이 바뀐다.

### F-19. 끌어다 놓아 열기 (P1, 2026-11-18 사용자 요청)

탐색기에서 md 파일이나 폴더를 창(트리·탭 줄·뷰어·편집기 어디든)에 끌어다 놓으면 연다.

- **md 파일(`.md`, `.markdown`):** 놓은 파일을 모두 고정 탭으로 연다(시작 인수·주소 표시줄과 같음). 놓은 순서대로 활성 탭 오른쪽에 붙고,
  첫 파일이 활성 탭이 되며 트리도 그 파일까지 펼쳐 고른다. 이미 열린 파일은 새 탭을 만들지 않고 그 탭을 쓴다.
  한 번에 여는 파일은 최대 20개다 — 폴더 전체를 고르다 실수로 수백 개를 놓아도 탭이 넘치지 않게 한다.
- **폴더:** md 파일 없이 폴더만 놓으면 트리가 첫 폴더로 이동해 펼친다(주소 표시줄과 같음).
- **섞어 놓으면:** md 파일이 하나라도 있으면 파일만 연다. 함께 놓은 폴더·md가 아닌 파일·20개를 넘은 파일은 건너뛰고 상태 표시줄에
  "열지 않은 항목 N개를 건너뛰었습니다 (md 파일·폴더만 열 수 있습니다)"를 보여 준다.
- **열 수 있는 것이 없으면:** 상태 표시줄에 "md 파일이나 폴더만 끌어다 놓을 수 있습니다"를 보여 준다. 끄는 동안에도 마우스 커서는
  파일 목록이면 "복사" 모양을 보이고, 글자 조각 같은 파일이 아닌 것은 "놓을 수 없음"을 보인다.
- 편집기 안에서 글자를 끌어 옮기는 동작은 그대로다(파일을 놓을 때만 앱이 처리한다). 큰 파일 확인(F-04)·없는 파일 알림은 열기와 같다.

**수용 기준**

- 탐색기에서 md 파일 하나를 뷰어에 놓으면 그 파일이 새 탭으로 열리고 트리에서 선택된다.
- md 파일 세 개를 놓으면 탭 세 개가 놓은 순서로 생기고 첫 파일이 보인다.
- 폴더를 놓으면 트리가 그 폴더로 이동한다. `.txt`만 놓으면 아무것도 열지 않고 상태 표시줄로 알린다.

### F-20. 뷰어 안 찾기 (P1, 2026-11-22 사용자 선택)

보기 모드에서 열린 문서의 글자를 찾는다. 편집 모드의 찾기(F-08, 편집기 안)와는 따로다.

- **열기:** 보기 모드에서 문서가 보일 때 `Ctrl+F`. 탭 줄과 문서 사이에 찾기 줄이 나타나고 입력란에 포커스가 간다. 포커스가 문서 영역에 있어도 열린다.
  이미 열려 있으면 입력란으로 포커스를 옮기고 글자를 모두 선택한다. 지난번에 찾던 글자는 입력란에 남아 있고, 다시 열면 그 글자로 바로 찾는다.
- **찾기:** 입력이 멈추고 **0.2초** 뒤에 찾는다. 찾은 곳은 모두 강조하고, 지금 가리키는 곳은 다른 색으로 강조하며 화면에 보이게 스크롤한다.
  대소문자는 구분하지 않는다. 접어 둔 `<details>` 안의 글자도 찾는다.
- **개수:** 입력란 옆에 `3/12`(지금 위치/전체)를 보여 준다. 찾은 곳이 없으면 "결과 없음"을 `Status.Danger` 색으로 보여 준다. 입력란이 비면 강조와 개수를 지운다.
- **이동:** `Enter`·`F3`·`▼` 버튼은 다음, `Shift+Enter`·`Shift+F3`·`▲` 버튼은 이전. 끝에서 다음을 누르면 처음으로, 처음에서 이전을 누르면 끝으로 돈다.
  글자를 치고 0.2초가 지나기 전에 `Enter`를 누르면 기다리지 않고 바로 찾는다.
- **닫기:** `Esc`(입력란·문서 영역 어디에 포커스가 있든) 또는 `×` 버튼. 강조를 지우고 포커스를 문서로 돌려준다.
- **문서가 바뀌면:** 찾기 줄을 연 채 다른 탭·다른 파일로 가거나 문서가 다시 읽히면(`F5`·자동 새로고침 F-18) 새 내용에서 같은 글자로 다시 찾는다 —
  옛 문서의 개수가 남지 않는다. 이때 처음 찾은 곳으로 스크롤한다.
- **편집 모드:** 찾기 줄은 보기 모드 전용이다. 편집 모드로 들어가면 닫히고, 편집 모드의 `Ctrl+F`는 지금처럼 편집기 안 찾기다. 문서가 보이지 않으면(탭 없음·읽기 실패 안내) 열리지 않고, 열려 있었으면 닫힌다.
- **범위 밖:** 대소문자 구분·단어 단위 찾기, 도움말 창 안 찾기, 편집 모드의 미리보기 안 찾기.

**수용 기준**

- 보기 모드에서 `Ctrl+F`를 누르고 문서에 여러 번 나오는 글자를 치면 `1/N`이 보이고, `Enter`를 누르면 `2/N`이 된다. `Esc`를 누르면 찾기 줄이 사라진다.
- 찾기 줄을 연 채 다른 문서를 열면 개수가 그 문서 기준으로 바뀐다.

### F-21. 목차 패널 (P1, 2026-11-22 사용자 선택)

열린 문서의 제목을 목록으로 보여 주고, 고르면 그 제목으로 간다.

- **위치:** 문서 영역 오른쪽의 패널(사용자 결정). 기본 너비 260, 문서와의 사이 구분선을 끌어 너비를 바꾼다(너비는 저장하지 않는다).
- **여닫기:** 툴바의 목차 버튼 또는 `Ctrl+Shift+B`. 처음에는 닫혀 있다. 여닫은 상태는 설정에 저장해 다음 실행에 되살린다(사용자 결정, F-14).
- **보기 모드 전용(사용자 결정):** 편집 모드에서는 패널을 열어 두었어도 숨기고, 보기 모드로 돌아오면 다시 보인다. 문서가 보이지 않을 때(탭 없음·읽기 실패 안내)도 숨긴다.
- **내용:** Markdown 제목(`#`~`######`, 밑줄 방식 포함)을 문서 순서대로, 단계만큼 들여 써서 보여 준다. 제목 안의 강조·코드·링크는 글자만 보여 준다.
  원시 HTML로 쓴 `<h2>` 같은 제목과 YAML front matter는 넣지 않는다.
- **이동:** 항목을 누르거나 키보드로 고르면(`↑`/`↓`) 문서가 그 제목으로 스크롤한다. 같은 제목이 여러 번 나와도 각자 자기 위치로 간다.
- **갱신:** 다른 탭·다른 파일로 가거나 문서가 다시 읽히면(`F5`·자동 새로고침 F-18) 목차도 바뀐다.
- **빈 상태:** 제목이 없는 문서면 "제목이 없습니다"를 보여 준다.
- **범위 밖:** 지금 보고 있는 위치의 제목 강조(스크롤 따라가기), 편집 모드의 목차, 단계 접기, 도움말 창(이미 목차가 있다).

**수용 기준**

- 제목이 여러 단계인 문서를 열고 목차를 켜면 제목이 단계대로 들여 써져 보이고, 아래쪽 제목을 고르면 문서가 그 제목으로 스크롤한다.
- 다른 문서를 열면 목차가 그 문서의 제목으로 바뀐다. 편집 모드로 들어가면 패널이 사라지고 보기 모드로 돌아오면 다시 나온다.
- 목차를 켠 채 닫고 다시 실행하면 목차가 켜져 있다.

### F-22. 코드 블록 구문 색상 (P1, 2026-11-22 사용자 선택)

- **무엇:** 언어를 적은 코드 블록(```` ```csharp ````)의 주석·문자열·키워드·숫자·함수·형식·태그·속성을 색으로 구분한다. 밝게·어둡게 테마 모두 색을 따로 둔다(03 §6.1).
- **언어:** 64개(C#, C/C++, Java, JavaScript/TypeScript, Python, Go, Rust, JSON, YAML, XML, HTML, CSS, SQL, 셸 스크립트, PowerShell, 배치 파일, Dockerfile, diff, Markdown 등).
  언어 이름은 대소문자를 가리지 않고, 흔한 줄임말(`cs`, `js`, `ts`, `py`, `sh`, `bash`, `yml`, `ps1`)도 알아본다.
- **색을 입히지 않는 경우:** 언어를 적지 않았거나 모르는 언어, 들여쓰기 코드 블록, 인라인 코드, 아주 큰 블록(5만 자 초과)은 지금처럼 한 색으로 보인다.
- **표시 순서 (2026-11-22 사용자 결정):** 문서는 지금처럼 바로 보여 주고, 색은 뒤에서 입혀 스크롤 위치를 유지한 채 본문을 한 번 더 바꾼다 — 색을 입히는 데
  코드 200줄에 약 0.15초, 앱을 켠 뒤 처음에는 약 1초가 더 걸려(측정, 02 §17.13) 한 번에 보여 주면 코드가 많은 문서가 표시 목표(§7)를 넘기 때문이다.
  한 번 색을 입힌 블록은 기억해 두어, 같은 문서를 다시 열거나 새로고침하거나 편집 미리보기를 갱신할 때는 처음부터 색이 입혀져 나온다.
- **적용 범위:** 뷰어, 편집 미리보기. 편집기(왼쪽 원문)의 색은 F-08 그대로다. 도움말 창은 색을 입히지 않는다.
- **보안:** 색은 렌더링 단계(C#)에서 입힌다. 문서 안 스크립트는 여전히 실행되지 않고(§7), 코드 글자는 지금처럼 이스케이프한다.

**수용 기준**

- ```` ```csharp ````·```` ```json ````·```` ```bash ```` 블록이 밝게/어둡게 테마에서 색으로 구분되어 보인다.
- 언어가 없거나 모르는 언어의 블록은 색 없이 지금과 똑같이 보인다.
- 코드가 많은 문서도 글은 바로 보이고(§7 표시 목표), 색은 잠시 뒤에 나타난다. 그사이 스크롤 위치가 바뀌지 않는다.
- 색이 나타나기 전에 다른 문서로 옮기면, 앞 문서의 색이 새 문서 위에 덮이지 않는다.

### F-23. 창 하나로 열기 — 단일 인스턴스 (P1, 2026-11-22 사용자 선택)

이미 MDFileViewer 창이 열려 있을 때 다시 실행하면(탐색기 우클릭 메뉴, 바로 가기, 명령줄) 새 창을 띄우지 않고 그 창에서 연다.
탐색기에서 파일을 하나씩 열 때마다 창이 쌓이지 않게 한다.

- **설정:** 더보기(`⋯`) 메뉴의 체크 항목 **창 하나로 열기**. 켜져 있으면(기본값) 이미 열린 창에서 열고, 끄면 지금까지처럼 실행할 때마다
  새 창을 연다. 바꾸면 바로 저장하고 **다음 실행부터** 적용한다. 바꾼 직후 상태 표시줄에 "다음 실행부터 이미 열린 창에서 엽니다" /
  "다음 실행부터 실행할 때마다 새 창을 엽니다"를 보여 준다.
- **넘겨받은 요청을 여는 방식 (창 하나로 열기가 켜져 있을 때):**

| 다시 실행한 형태 | 이미 열린 창의 동작 |
|------------------|---------------------|
| md 파일 경로 | 창을 맨 앞으로 올리고 그 파일을 **고정 탭**으로 연다(이미 열려 있으면 그 탭으로 간다). 트리도 그 파일까지 펼쳐 고른다. 보던 탭은 그대로 둔다 |
| 폴더 경로(md가 아닌 파일 경로 포함) | 창을 맨 앞으로 올리고 트리를 그 폴더로 옮긴다. 열린 문서는 그대로 둔다 |
| 인수 없음 | 창을 맨 앞으로 올리기만 한다. 지난 탭을 되살리거나 폴더를 옮기지 않는다 |
| 없는 경로 | 창을 맨 앞으로 올리고 "경로를 찾을 수 없습니다: <경로>"를 알린다(F-01과 같은 알림) |
| `--register` / `--unregister` | 넘기지 않는다 — 실행한 쪽이 지금처럼 직접 처리하고 끝난다 |

- **창을 맨 앞으로:** 최소화돼 있으면 최소화 전 상태(보통·최대화)로 되돌린다. Windows가 맨 앞으로 올리는 것을 막으면 작업 표시줄 단추만
  깜박일 수 있다.
- **대화상자가 떠 있을 때:** 이미 열린 창이 대화상자(저장 확인 등)를 띄운 중이면 그 대화상자를 맨 앞으로 올리고, 대화상자가 닫힌 뒤에 연다.
- **여러 개를 한꺼번에:** 탐색기에서 md 파일 여러 개를 골라 열면 앱이 그 수만큼 동시에 실행된다. 하나만 창을 띄우고 나머지는 그 창에
  넘겨, 모두 한 창의 탭으로 열린다. 창이 뜨는 중에 넘어온 요청은 창이 준비된 뒤에 온 순서대로 연다.
- **넘기지 못하면:** 이미 열린 창이 5초 안에 받지 못하면(닫히는 중 등) 요청을 잃지 않도록 자기 창을 띄워 연다.
- **범위:** 같은 Windows 사용자 세션 안에서만 모은다. 다른 사용자가 연 창으로는 넘기지 않는다.
- **끌어다 놓기(F-19)·지난 탭 복원(F-17)과의 관계:** 끌어다 놓기는 그대로다. 지난 탭 복원은 창을 새로 띄우는 실행에서만 한다.
- **설정 파일(F-14):** 창이 하나면 여러 창이 설정을 서로 덮어쓰는 제약이 생기지 않는다.

**수용 기준**

- 창이 열린 상태에서 탐색기 우클릭 메뉴로 다른 md 파일을 열면, 새 창 없이 기존 창에 탭이 하나 더 생기고 그 문서가 보인다.
- `⋯` → **창 하나로 열기**를 끄고 다시 실행하면 새 창이 따로 뜬다. 다시 켜고 실행하면 기존 창에서 열린다.
- 탐색기에서 md 파일 세 개를 골라 한꺼번에 열면 창 하나에 탭 세 개가 생긴다.
- 편집 중인 탭의 저장 확인 대화상자가 떠 있을 때 다른 파일을 열면, 대화상자에 답한 뒤에 그 파일이 열린다.

### F-25. Mermaid 다이어그램 (P1, 2026-11-22 사용자 요청)

- **무엇:** 언어를 `mermaid`로 적은 코드 블록(```` ```mermaid ````)을 그림으로 보여 준다. 상태 다이어그램(FSM), 순서도, 시퀀스 다이어그램 등
  Mermaid가 지원하는 그림을 문서에 적힌 문법 그대로 그린다. 사용자가 다루는 문서에 FSM이 Mermaid 문법으로 적혀 있어 넣었다.
- **라이브러리 (2026-11-22 사용자 승인):** `mermaid` 11.17.2(MIT)를 앱에 넣는다(`mermaid.min.js`, 3.6MB). 네트워크에서 받지 않는다.
  12.x는 EPL-2.0인 ELK(`elkjs`)가 한 파일에 묶여 있어 쓰지 않는다(02 §11 PoC-9).
- **표시 순서:** 문서는 지금처럼 바로 보여 주고(코드 블록 모양), 그림은 뒤에서 그려 코드 블록을 바꾼다. 라이브러리는 그림이 든 문서를
  처음 볼 때만 읽으므로, 그림이 없는 문서와 앱 시작 시간은 그대로다. 한 번 그린 그림은 기억해 두어 같은 본문을 다시 넣을 때(새로고침,
  구문 색상 2단계, 편집 미리보기)는 코드 블록이 잠깐 보였다 사라지지 않는다.
- **테마:** 밝게·어둡게 테마에 맞춰 그리고, 테마를 바꾸면 다시 그린다(03 §6.2).
- **그리지 못하는 블록:** 문법이 틀린 블록은 코드 블록 원문 그대로 둔다. 오류 그림이나 안내를 문서에 끼워 넣지 않는다.
- **넓은 그림:** 뷰어 폭보다 넓으면 그림 상자 안에서 가로로 스크롤한다.
- **적용 범위:** 뷰어, 편집 미리보기. 도움말·릴리즈 노트 창도 같은 템플릿을 쓰므로 같은 규칙이 적용된다(내장 문서에는 Mermaid 블록이 없다).
- **보안:** 그림을 그리려고 뷰어에서 **앱 폴더의 스크립트만** 실행을 허용한다(`viewer.js`, `mermaid.min.js`). 문서 안의 스크립트·이벤트 속성·
  `javascript:` 링크는 여전히 실행되지 않는다(§7, 02 §6.5). 그림은 Mermaid의 `strict` 수준으로 그린다 — 그림 원문에 넣은 스크립트·이벤트 속성을
  지우고 클릭 동작을 만들지 않는다(그림 글자 안의 `<img>` 같은 태그는 정화된 채 남을 수 있다 — 문서 본문의 HTML과 같은 제한을 받는다).
- **넣지 않는 것:** 수식(KaTeX 등)은 넣지 않는다(§8). 그림을 파일로 내보내기, 그림 확대·이동도 없다.
- **알려진 한계:** 그림은 문서가 보인 뒤에 그려지므로 그 아래 내용이 밀린다 — 앵커 링크로 열었을 때의 위치, 복원한 스크롤 위치, 찾기(F-20)의
  결과 개수가 그림이 그려지기 전 기준일 수 있다. 목차(F-21)는 제목만 다루므로 영향이 없다.

**수용 기준**

- ```` ```mermaid ```` 상태 다이어그램·순서도가 든 문서를 열면 밝게/어둡게 테마에서 그림으로 보인다.
- 문법이 틀린 블록은 코드 블록으로 남고, 같은 문서의 다른 그림과 글은 정상으로 보인다.
- Mermaid 블록이 없는 문서를 열 때는 라이브러리를 읽지 않는다.
- `<script>`·`onerror`·`javascript:` 링크가 든 문서, 그림 원문 안에 HTML·스크립트를 넣은 문서를 열어도 스크립트가 실행되지 않는다.
- 그림이 그려지기 전에 다른 문서로 옮기면, 앞 문서의 그림이 새 문서에 끼어들지 않는다.
