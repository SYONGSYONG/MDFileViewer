# 03. 디자인 — 어떻게 보이는가

## 1. 디자인 방향 — "종이와 잉크"

- **문서가 주인공이다.** 앱 크롬(툴바, 트리, 상태 표시줄)은 따뜻한 회색 톤으로 한 단계 물러서고,
  문서 영역은 한 단계 밝은(어둡게 테마에서는 한 단계 떠 있는) "종이" 면으로 둔다. 면의 높낮이로 시선을 문서에 모은다.
- **색은 의미로만 쓴다.**
  - 파랑(`Accent`) — 링크, 선택, 키보드 포커스
  - 호박색(`Mode.Edit`) — "지금 파일을 바꿀 수 있는 상태"
  - 빨강(`Status.Danger`) — 오류, 저장하지 않은 변경
  - 초록(`Status.Success`) — 저장 완료
  - 그 밖의 장식용 색은 쓰지 않는다.
- **위계는 크기 대비로 만든다.** 문서 제목 단계는 크기·굵기 차이를 분명히 두고, UI 글자는 작고 차분하게 둔다.
- **Windows 11과 어울리게** Segoe 계열 글꼴과 Segoe Fluent Icons를 쓴다. 글꼴을 따로 넣지 않는다(의존성 없음).

- 트리 | 뷰어 2열이다. md 파일은 별도 목록 창 없이 트리의 폴더 아래에(하위 폴더 다음에) 보인다 (01 F-02·F-03, 2026-11-17 사용자 결정).

- 창 기본 크기 1440×900, 최소 900×560.
- 창은 마우스 커서가 있는 모니터의 가운데에 뜬다. 그 모니터의 작업 영역(작업 표시줄을 뺀 영역)에 기본 크기가 들어가지 않으면
  넘치는 쪽(너비·높이 각각)을 작업 영역의 90%로 줄이고 작업 영역 가운데에 띄운다(크기는 맞는데 작업 영역 밖으로 나가 있으면 크기는 두고
  가운데로만 옮긴다). 90%면 창 테두리와 바탕 화면이 조금 보여
  최대화한 창과 구별된다. 줄여도 최소 크기보다 작게 하지는 않고, 작업 영역이 최소 크기보다 작으면 작업 영역에 맞춘다.
  예: 2560×1600·200% 모니터의 작업 영역은 1280×752 DIP라 기본 크기(1440×900)가 넘친다 → 1152×677 DIP 정도로 뜬다.
  (2026-11-17 사용자 지적: 200% 모니터에서 창이 화면을 넘어 위쪽이 잘렸다.)

**Phase 4 구현 세부 (2026-11-17):**

- 툴바는 폴더 열기 버튼과 주소 표시줄만 먼저 넣었다. 나머지(모드 전환·저장·줌·테마·도움말·더보기)는 해당 Phase에서 §3 순서대로 더한다.
- 상태 표시줄 구획(왼쪽부터): 일시 메시지가 있으면 그 메시지, 없으면 문서 경로 │ 인코딩 │ 줄 끝 │ 크기 │ 수정 시각 │ 경고(손상 안내, `Status.Danger`).
  값이 없는 구획은 접는다. 경로·메시지는 최대 560px에서 줄인다. (목록 창이 있던 때의 오른쪽 끝 md 파일 개수는 트리 통합으로 없앴다.)
- 트리 행: 머리 행 높이 최소 26px, 하위 단계 들여쓰기 16px. 펼침 화살표는 글꼴 글리프 대신 `Path`로 그린 꺾쇠(›)이고 펼치면 90° 돈다
  (Segoe Fluent Icons가 없는 PC에서도 같게 보이게). 키보드 포커스 링은 펼친 자식까지 감싸지 않고 머리 행(26px)에만 그린다.
  md 파일 행은 펼침 화살표 자리를 비워 두고 문서 아이콘(§9)을 쓴다 — 폴더 행과 이름의 시작 위치가 맞는다.
- 트리 자동 스크롤은 누가 선택을 옮겼는지에 따라 다르다.
  - **사용자가 클릭·키보드로 고를 때:** 가로 스크롤은 그대로 두고, 행이 화면 위·아래로 벗어났을 때만 세로로 최소한만 스크롤한다.
    WPF 기본 동작은 포커스를 받은 항목 전체를 보이게 하려고 가로로 크게 밀어(이름이 긴 깊은 행에서 행 왼쪽 끝까지), 클릭할 때마다
    트리가 옆으로 움직였다(2026-11-17 사용자 지적).
  - **앱이 고를 때(시작 경로·주소 이동·링크·`F5`):** 행이 보이지 않으면 대상 행을 화면 맨 위가 아니라 위에서 1/3 지점에 둔다 — 부모 폴더가
    함께 보인다. 가로로는 행의 왼쪽 끝(펼침 화살표)이 화면 밖일 때만 그 끝이 보이게 맞춘다.
- 대화상자는 앱 테마를 따르는 자체 창(`MessageDialog`)으로 띄운다: 본문 + 기본 버튼(굵게, `Enter`) + 보조 버튼(`Esc`). 시스템 메시지 상자는
  프로세스가 끝나는 오류에서만 쓴다.

- 왼쪽 `>` 줄(폭 24px)은 접힌 탐색 패널이다. 누르거나 `Ctrl+B`를 누르면 트리가 펼쳐진다. (검토 항목 1)
- 편집기 | 미리보기 기본 비율은 50:50이고, 가운데 구분선으로 바꾼다.
- **서식 도구 모음 (01 F-28, 2026-11-24):** 편집기 열의 맨 위 한 줄(버튼 높이 28, 아래 테두리). 편집기 열에만 있고 미리보기
  위로는 넘어가지 않는다. `[본문 ▾] │ [B][I][S][<>][링크] │ [•][1.][[ ]][>] │ [찾기·바꾸기]`. 제목 단계는 글자 버튼(지금 단계 이름 + `▾`)이고
  누르면 메뉴(본문, 제목 1~6 — 지금 단계에 체크)가 뜬다. 서식 버튼은 28×28 `ToolbarButton`, 글리프 대신 **글자**로 그린다(`B` 굵게,
  `I` 기울임, `S` 취소선 등 — 아이콘 글꼴에 마땅한 모양이 없는 것이 많고 글자가 더 바로 읽힌다). 구분은 `ToolbarSeparator`.
  버튼 얼굴은 Markdown 기호를 닮게 했다(작업 목록 `[ ]`, 인용 `>`). 편집기 폭이 좁아 버튼이 넘치면 다음 줄로 넘어간다(`WrapPanel`).
  버튼은 포커스를 받지 않는다 — 눌러도 편집기의 선택이 남는다. 키보드로는 단축키를 쓴다.
- **찾기·바꾸기 줄 (01 F-28):** 도구 모음 아래 한 줄(좁으면 다음 줄로 넘어간다). `[찾을 말] [바꿀 말] 3개 [∧][∨] [바꾸기][모두 바꾸기] [Aa] [×]`.
  입력란은 `AddressBox` 스타일, 개수는 `Text.Secondary`(없으면 `Status.Danger`), `Aa`(대소문자 구분)는 켜지면 `Accent` 테두리와 `Surface.Selected` 바탕(`ToolbarToggle` 스타일).
  보기 모드의 찾기 줄(§2.5)과 같은 모양을 쓰되 편집기 열 안에 있다.

### 2.3 목록 창을 없앤 이유 (검토 항목 7 변경, 2026-11-17)

- 처음 확정안은 트리 | 목록 | 뷰어 3열이었고, 대안으로 왼쪽 상하 분할(트리 위·목록 아래)을 두었다.
- Phase 4 실행 화면을 본 사용자가 폴더와 파일을 한곳에서 보기로 정했다. 트리에 md 파일을 합쳐 뷰어 폭이 목록 창 너비(300px)만큼 넓어지고,
  폴더를 고른 뒤 다시 옆 창으로 눈을 옮기지 않아도 된다. 잃는 것은 하위 폴더 전체 목록·날짜·크기 열·정렬이다 — 크기·수정 시각은
  상태 표시줄에 있고, 전체 검색은 후속 후보(01 §8)로 둔다.

### 2.5 찾기 줄 (01 F-20, 2026-11-22)


- 보기 모드에서 `Ctrl+F`로 탭 줄과 문서 사이에 끼운다. 문서 위에 겹쳐 띄우지 않는다 — WebView2 위에는 WPF 요소를 겹칠 수 없다(§8 끌어다 놓기와 같은 이유).

  이전·다음 버튼(툴바 버튼 스타일, 28×28), 오른쪽 끝에 닫기 버튼.
- 개수는 `3/12`. 찾은 곳이 없으면 "결과 없음"을 `Status.Danger`로 쓴다(글자 색 대비 4.8·7.0:1, §4). 입력란이 비면 이전·다음 버튼은 비활성(글자를 치고 바로 `Enter`를 누를 수 있게, 찾은 곳이 없을 때는 막지 않는다).
- 글리프: 이전 E70E(ChevronUp), 다음 E70D(ChevronDown), 닫기 E711. 버튼마다 툴팁(단축키 포함)과 접근성 이름을 단다.
- 문서 안 강조 색은 WebView2(Chromium) 기본값이다: 찾은 곳 노랑, 지금 위치 주황, 세로 스크롤바에 위치 표시(02 §17.11).

### 2.7 불러오는 중 표시 (2026-11-25)

문서를 읽는 동안 화면이 멈춘 것처럼 보이지 않게, 문서 영역 맨 위에 가는 진행 막대를 흘린다.

- **위치·모양:** 문서 영역(뷰어) 바로 위, 높이 2px, 강조색(`Accent`), 테두리·바탕 없음. WebView2 위에는 WPF 요소를 겹칠 수 없어 자리를 따로 두며,
  그 2px은 늘 차지한다 — 나타나고 사라질 때 문서가 밀리지 않는다.
- **늦게 나타난다:** 읽기 시작 뒤 0.2초(`AppConstants.LoadingIndicatorDelay`)가 지나도 끝나지 않을 때만 보인다. 켜 놓은 뒤 여는 문서는 대개 0.1초 안에
  보여, 바로 띄우면 깜빡임이 된다(05 14-4 측정). 읽기가 끝나면(성공·실패·취소) 바로 사라진다.
- **문구:** 보여 줄 문서가 아직 없을 때(프로그램을 켠 직후)는 가운데 안내 문구도 "불러오는 중…"으로 바꾼다. 이전 문서가 보이는 중이면 막대만 흐른다.
- **큰 스피너·덮개를 쓰지 않는 이유:** 뷰어는 금방 끝나는 일이 대부분이라, 화면을 가리는 표시는 끝난 뒤에 더 거슬린다.
- **한계:** 막대는 UI 스레드가 돌아야 움직인다 — 형제가 수천 개인 폴더에서 트리를 맞추는 동안(알려진 한계)에는 멈춰 보인다.

| 파일 작업 실패 | 작업하지 못함 | 문서를 만들지 / 이름을 바꾸지 / 삭제하지 못했습니다. (작업별 문구) | **확인** |

- 굵은 버튼이 기본 버튼(`Enter`)이다.
- **입력 창 (01 F-27):** 메시지 대화상자와 같은 폭(420)·바탕·버튼 줄. 위에서부터 설명 한 줄, 입력란(주소 표시줄과 같은 스타일), 이유 한 줄
  (`Status.Danger` 색). 이유 줄은 비어 있어도 한 줄 높이를 지킨다 — 입력하는 동안 창 높이가 출렁이지 않게. 이유가 있는 동안 기본 버튼은 꺼진다.
  처음 뜰 때 입력란에 포커스가 가고 확장자를 뺀 이름이 선택되어 있다. 이유 줄은 화면 읽기 프로그램이 바뀔 때 읽는다(`LiveSetting=Polite`).
  실제 문구는 `UiText`가 기준이다.
