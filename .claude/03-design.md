# 03. 디자인 — 어떻게 보이는가

## 1. 디자인 방향 — "종이와 잉크"

- **문서가 주인공이다.** 앱 크롬(툴바, 트리, 상태 표시줄)은 따뜻한 회색 톤으로 한 단계 물러서고,
  문서 영역은 한 단계 밝은(어둡게 테마에서는 한 단계 떠 있는) "종이" 면으로 둔다. 면의 높낮이로 시선을 문서에 모은다.
- **색은 의미로만 쓴다.**
  - 파랑(`Accent`) — 링크, 선택, 키보드 포커스
  - 호박색(`Mode.Edit`) — "지금 파일을 바꿀 수 있는 상태"
  - 빨강(`Status.Danger`) — 오류, 저장하지 않은 변경
  - 초록(`Status.Success`) — 저장 완료
  - 그 밖의 장식용 색은 쓰지 않는다.
- **위계는 크기 대비로 만든다.** 문서 제목 단계는 크기·굵기 차이를 분명히 두고, UI 글자는 작고 차분하게 둔다.
- **Windows 11과 어울리게** Segoe 계열 글꼴과 Segoe Fluent Icons를 쓴다. 글꼴을 따로 넣지 않는다(의존성 없음).

- 트리 | 뷰어 2열이다. md 파일은 별도 목록 창 없이 트리의 폴더 아래에(하위 폴더 다음에) 보인다 (01 F-02·F-03, 2026-11-17 사용자 결정).
- 두 영역 사이에는 끌어서 너비를 바꾸는 구분선(GridSplitter)이 있다.
- 기본 너비: 트리 320, 뷰어는 나머지. 최소 너비: 트리 160, 뷰어 320. 트리에 파일 이름도 들어가므로 목록 창이 있던 때(260)보다 넓게 둔다.
- 창 기본 크기 1440×900, 최소 900×560.
- 창은 마우스 커서가 있는 모니터의 가운데에 뜬다. 그 모니터의 작업 영역(작업 표시줄을 뺀 영역)에 기본 크기가 들어가지 않으면
  넘치는 쪽(너비·높이 각각)을 작업 영역의 90%로 줄이고 작업 영역 가운데에 띄운다(크기는 맞는데 작업 영역 밖으로 나가 있으면 크기는 두고
  가운데로만 옮긴다). 90%면 창 테두리와 바탕 화면이 조금 보여
  최대화한 창과 구별된다. 줄여도 최소 크기보다 작게 하지는 않고, 작업 영역이 최소 크기보다 작으면 작업 영역에 맞춘다.
  예: 2560×1600·200% 모니터의 작업 영역은 1280×752 DIP라 기본 크기(1440×900)가 넘친다 → 1152×677 DIP 정도로 뜬다.
  (2026-11-17 사용자 지적: 200% 모니터에서 창이 화면을 넘어 위쪽이 잘렸다.)

**Phase 4 구현 세부 (2026-11-17):**

- 툴바는 폴더 열기 버튼과 주소 표시줄만 먼저 넣었다. 나머지(모드 전환·저장·줌·테마·도움말·더보기)는 해당 Phase에서 §3 순서대로 더한다.
- 상태 표시줄 구획(왼쪽부터): 일시 메시지가 있으면 그 메시지, 없으면 문서 경로 │ 인코딩 │ 줄 끝 │ 크기 │ 수정 시각 │ 경고(손상 안내, `Status.Danger`).
  값이 없는 구획은 접는다. 경로·메시지는 최대 560px에서 줄인다. (목록 창이 있던 때의 오른쪽 끝 md 파일 개수는 트리 통합으로 없앴다.)
- 트리 행: 머리 행 높이 최소 26px, 하위 단계 들여쓰기 16px. 펼침 화살표는 글꼴 글리프 대신 `Path`로 그린 꺾쇠(›)이고 펼치면 90° 돈다
  (Segoe Fluent Icons가 없는 PC에서도 같게 보이게). 키보드 포커스 링은 펼친 자식까지 감싸지 않고 머리 행(26px)에만 그린다.
  md 파일 행은 펼침 화살표 자리를 비워 두고 문서 아이콘(§9)을 쓴다 — 폴더 행과 이름의 시작 위치가 맞는다.
- 트리 자동 스크롤은 누가 선택을 옮겼는지에 따라 다르다.
  - **사용자가 클릭·키보드로 고를 때:** 가로 스크롤은 그대로 두고, 행이 화면 위·아래로 벗어났을 때만 세로로 최소한만 스크롤한다.
    WPF 기본 동작은 포커스를 받은 항목 전체를 보이게 하려고 가로로 크게 밀어(이름이 긴 깊은 행에서 행 왼쪽 끝까지), 클릭할 때마다
    트리가 옆으로 움직였다(2026-11-17 사용자 지적).
  - **앱이 고를 때(시작 경로·주소 이동·링크·`F5`):** 행이 보이지 않으면 대상 행을 화면 맨 위가 아니라 위에서 1/3 지점에 둔다 — 부모 폴더가
    함께 보인다. 가로로는 행의 왼쪽 끝(펼침 화살표)이 화면 밖일 때만 그 끝이 보이게 맞춘다.
- 대화상자는 앱 테마를 따르는 자체 창(`MessageDialog`)으로 띄운다: 본문 + 기본 버튼(굵게, `Enter`) + 보조 버튼(`Esc`). 시스템 메시지 상자는
  프로세스가 끝나는 오류에서만 쓴다.

### 2.3 목록 창을 없앤 이유 (검토 항목 7 변경, 2026-11-17)

- 처음 확정안은 트리 | 목록 | 뷰어 3열이었고, 대안으로 왼쪽 상하 분할(트리 위·목록 아래)을 두었다.
- Phase 4 실행 화면을 본 사용자가 폴더와 파일을 한곳에서 보기로 정했다. 트리에 md 파일을 합쳐 뷰어 폭이 목록 창 너비(300px)만큼 넓어지고,
  폴더를 고른 뒤 다시 옆 창으로 눈을 옮기지 않아도 된다. 잃는 것은 하위 폴더 전체 목록·날짜·크기 열·정렬이다 — 크기·수정 시각은
  상태 표시줄에 있고, 전체 검색은 후속 후보(01 §8)로 둔다.

## 3. 툴바 구성 (왼쪽 → 오른쪽)

| 순서 | 요소 | 동작 |
|------|------|------|
| 0 | 탐색 패널 버튼 | 탐색 패널(트리) 접기/펴기 (`Ctrl+B`). 보기·편집 모드 모두 (2026-11-18 사용자 요청) |
| 1 | 폴더 열기 버튼 | 폴더 선택 대화상자 (`Ctrl+O`) |
| 2 | 주소 표시줄 | 현재 폴더 경로. 입력 후 `Enter`로 이동. 남는 폭을 차지한다 |
| 3 | 모드 전환 토글 | `편집` ↔ `보기` (`Ctrl+E`). 편집 모드에서 활성 상태로 표시 |
| 4 | 저장 버튼 | 편집 모드에서만 보인다. 미저장 시 빨간 점 |
| 5 | 줌 그룹 | `[-] 100% [+]`. 가운데 표시를 누르면 100% |
| 6 | 테마 버튼 | 메뉴: 시스템 설정 따르기 / 밝게 / 어둡게 (현재 항목에 체크) |
| 7 | 도움말 버튼 `?` | 도움말 창 (`F1`) |
| 8 | 더보기 `…` | 탐색기 메뉴 등록 / 탐색기 메뉴 해제 / 정보 |

- "정보"는 대화상자(제목 "MDFileViewer 정보")로 앱 이름·버전·WebView2 Runtime 버전·로그 폴더 경로를 보여 준다(2026-11-18).
  그 아래 빈 줄 뒤에 "© 2026 SYONG · MIT 라이선스"와 "라이선스·제3자 고지(앱 폴더):"를 보이고, 파일 이름 "LICENSE.txt, THIRD-PARTY-NOTICES.txt"는 다음 줄에 따로 둔다(2026-11-18 사용자 결정, 02 §15.2 —
  한 줄에 두면 420px 대화상자에서 `THIRD-PARTY-` 뒤에서 끊겼다).

- 그룹 사이에 세로 구분선을 둔다. 아이콘 버튼은 32×32, 아이콘 16px.
- 모든 아이콘 버튼에 툴팁(단축키 포함, 예: "편집 모드 (Ctrl+E)")과 접근성 이름을 단다.

`Text.Secondary`는 `Surface.Document`·`Chrome`·`Panel`·`Selected` 위에서 4.8~6.9:1, `Accent`/`Surface.Document` 4.7·6.6:1, `Status.Danger`/`Surface.Chrome` 4.8·7.0:1,
`Status.Success`/`Surface.Chrome` 4.8·9.1:1. 편집기 구문 강조 12색(§7)은 `Surface.Document` 위에서 4.7~8.2:1. `Text.Disabled`는 2.7:1로 기준 아래지만 비활성 요소·줄 번호에만 쓴다(WCAG는 비활성 요소를 기준에서 뺀다).
`Border.Strong`은 처음 값(`#B9B4AA`·`#454B56`)이 2.1·1.8:1로 비텍스트 3:1에 못 미쳐, 같은 회색 계열에서 명도만 낮춰(어둡게 테마는 높여) 바꿨다(사용자 결정).

- `Accent`는 밝게 테마의 `Surface.Chrome` 위에서 글자색으로 쓰면 4.5:1에 못 미치므로, 크롬 위에서는 포커스 링·선택 막대(비텍스트)로만 쓴다.

## 6. 문서 스타일 (`viewer.css`)

- **본문 폭:** 최대 폭 없이 뷰어 폭을 다 쓴다(2026-11-18 사용자 결정 — 860px 제한은 넓은 표를 가로 스크롤시켰다). 좌우 여백 40px, 위 32px, 아래 64px. 뷰어 폭이 640px 이하이면 좌우 여백 16px.
  문서의 첫 요소는 위 여백을, 마지막 요소는 아래 여백을 없앤다(첫 제목이 툴바에서 너무 멀어지지 않게).
- **링크:** `Accent` 색, 평소에는 밑줄 없이, 마우스를 올리면 밑줄.
- **코드:** 인라인 코드는 `Code.Background` 배경 + 좌우 0.3em 여백 + 모서리 4px. 코드 블록은 안쪽 여백 12px 16px, 모서리 6px, 긴 줄은 블록 안에서만 가로 스크롤.
- **표:** `Border.Subtle` 테두리, 머리글 행은 `Surface.Panel` 배경과 굵게, 셀 여백 6px 12px. 표는 본문 폭(= 뷰어 폭에서 여백을 뺀 폭)까지
  넓어진다. 표 칸의 짧은 하이픈 단어(`0-1`, `2026-11-17`, 공백 없이 20자 이하)는 하이픈에서 줄을 바꾸지 않는다
  (`.nobr`, 2026-11-18 사용자 지적 — 하이픈 뒤에서 끊겨 열이 `0-` 폭까지 줄었다).
  **창을 줄일 때 (2026-11-18 사용자 결정 — 단어 단위로만 끊으면 표가 최소 폭에서 멈춰 오른쪽이 잘려 보였다):** 칸 안은 공백에서 먼저 줄을 바꾸고
  (본문의 `keep-all`로 한글 단어 유지), 한 줄에 안 들어가는 긴 단어·경로·인라인 코드만 글자 사이에서 끊는다(`overflow-wrap: anywhere`).
  칸마다 최소 폭 `3em`을 둬 짧은 칸(`Core`, `상태`)은 글자 사이에서 끊지 않는다 — 최소 폭이 없으면 열이 많은 표가 한 글자씩 세로로 줄 바꿈되고
  (2026-11-18 사용자 지적), `4em`이면 열 여섯 개 표가 580px에서 모든 칸이 최소 폭에 붙어 긴 칸이 좁아졌다(headless Edge로 580·1400px 렌더 확인).
  열이 아주 많아 최소 폭의 합보다 좁아지면 마지막 수단으로 표만 가로 스크롤.
- **인용:** 왼쪽 4px `Quote.Bar` 막대, 글자는 `Text.Secondary`.
- **작업 목록:** 목록 기호 없이 비활성 체크박스로 보여 준다(뷰어에서는 체크를 바꿀 수 없다).
- **수평선:** 2px `Border.Subtle`.
- **이미지:** `max-width: 100%`, 높이는 비율 유지.
- **각주:** 본문 끝 구분선 아래 0.875em, `Text.Secondary`, 위 여백 2em.
- **코드 블록 줄 바꿈:** 본문의 `keep-all`·`anywhere` 줄 바꿈을 코드 블록에는 쓰지 않는다(들여쓰기·정렬 보존).
- **접기(`<details>`):** 스크립트 없이 브라우저가 펼치고 접는다. `<summary>`에 손가락 커서.
- **선택 영역:** `Accent` 25% 투명.
- **스크롤바:** `color-scheme`을 테마에 맞춰 두어 어둡게 테마에서 스크롤바도 어둡게 그린다.
